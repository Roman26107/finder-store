# Безопасность

- Реальные `.env`, базы, медиа, дампы, ключи и журналы не должны попадать в Git или Docker build context.
- Для каждого окружения создавайте новые Django, PostgreSQL, API и SMTP-секреты. Локальный fallback SECRET_KEY не предназначен для production.
- Вне localhost API работает по HTTPS. HMAC не заменяет TLS.
- Ограничивайте scope API-ключа и доступ к внутренним портам. Изменение роли пользователя проверяется сервером.
- Не публикуйте вывод `docker compose config`, переменные окружения или персональные сведения из логов.
- Если секрет когда-либо был опубликован, удаление файла или коммита недостаточно: отзовите ключ и выпустите новый.
- Проверяйте обновления зависимостей и результат `manage.py check --deploy` перед развёртыванием.

Не размещайте эксплойты, токены или персональные данные в публичных issues. Для приватного сообщения используйте приватный канал, указанный владельцем репозитория. Специальный security-контакт в этой портфолио-копии не настроен.
