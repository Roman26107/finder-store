# FINDER — интернет-магазин и панель управления

Серверное Django-приложение для каталога одежды и аксессуаров: от поиска и выбора размера до оформления заказа, персональных заявок и обработки заказов менеджером.

Публичная версия содержит исходный код и синтетический демокаталог. Производственные данные, пользовательские контакты, коммерческие фотографии, ключи и история развёртываний не включены.

## Возможности

- Каталог с фильтрами, сортировкой, пагинацией, цветовыми и размерными вариантами.
- Адаптивная витрина, галереи фотографий и редакционный «Образ недели».
- Корзина, избранное, промокоды и варианты доставки.
- Регистрация, подтверждение e-mail, восстановление пароля, адресная книга и история заказов.
- Персональная заявка на поиск вещи с загрузкой фотографии.
- Панель `/control/`: товары, заказы, заявки, баннеры, подборки и аналитика.
- Импорт каталогов, нормализация структуры и редакционные правила обработки текстов.
- Подписанный API для отдельного Telegram-бота, контроль повторных запросов и идемпотентность.
- Конфигурации Nginx, PostgreSQL и зашифрованных резервных копий Restic/S3.

Онлайн-эквайринг не реализован: приложение оформляет заказ, а не списывает деньги. Остатки импортируемых каталогов являются снимком источника, не гарантией наличия в реальном времени.

## Стек

Python 3.12, Django 5.2, PostgreSQL 16, Pillow, Gunicorn, Nginx. Интерфейс — Django Templates, CSS и JavaScript без этапа сборки Node.js. Для локальной демонстрации используется SQLite и консольная отправка e-mail.

## Быстрый запуск

Команды выполняются из корня этого репозитория.

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
```

Linux/macOS:

```bash
source .venv/bin/activate
cp .env.example .env
```

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

Сайт: `http://127.0.0.1:8000/`. Панель управления: `http://127.0.0.1:8000/control/`.

`seed_demo` создаёт восемь вымышленных товаров, 24 локально нарисованные иллюстрации, размеры, баннеры и подборку. Повторный запуск не дублирует товары. Пароли и аккаунты команда не создаёт. Коды входа сотрудников и подтверждения e-mail в локальном режиме выводятся в терминал Django.

## Проверки

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test shop
python manage.py collectstatic --noinput
```

На Linux с Bash доступен изолированный тест backup-скриптов:

```bash
bash deploy/backup/tests/smoke_test.sh
```

Тесты не требуют production-базы, рабочего Telegram-токена или реального SMTP. Демонстрационные картинки и SQLite создаются локально и исключены из Git.

При push и pull request GitHub Actions запускает тесты, проверку миграций, backup smoke-test и создание демокаталога с пустой базой. Workflow не использует production-секреты и ничего не развёртывает на сервере.

## Структура

```text
config/          настройки, URL, WSGI и ASGI
shop/            модели, витрина, панель управления, API, импорт и тесты
telegram_bot/    Django-модели привязки аккаунтов и доставки уведомлений
templates/       административные шаблоны и страницы ошибок
static/          стили, JavaScript и демонстрационные изображения
deploy/          Nginx, запуск контейнера, резервное копирование
docs/            архитектура, интеграция и эксплуатация
```

Polling-процесс Telegram вынесен в самостоятельный репозиторий `finder-telegram-bot`. Django-приложение `telegram_bot` здесь остаётся серверной частью интеграции, а не вторым экземпляром бота.

## Публикация

Это портфолио-копия, не дамп работающего магазина. Изображения демокаталога создаются программно; названия товаров вымышлены. Упоминания сторонних брендов в адаптерах импорта описывают поддерживаемые форматы, а не партнёрство с правообладателями.

Лицензия на распространение кода пока не назначена. Перед предоставлением прав третьим лицам владелец проекта должен выбрать условия лицензирования.
