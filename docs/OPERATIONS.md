# Развёртывание и резервное копирование

## Docker

В репозитории есть Dockerfile и Compose для PostgreSQL, web, Nginx и отдельного процесса обновления курсов. Redis не требуется. Бот разворачивается отдельно.

Скопируйте `.env.production.example` в `.env.production`. Перед запуском замените домен, пароль PostgreSQL и Django SECRET_KEY. Не используйте значения `replace-with-*` на настоящем сервере. Сначала настройте DNS и reverse proxy; пример не является готовой конфигурацией вашей инфраструктуры.

```bash
docker compose config --quiet
docker compose up -d --build db web nginx
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py check --deploy
```

В контейнере web при старте выполняются миграции и `collectstatic`. PostgreSQL и Gunicorn не публикуют порты хоста. Nginx публикует 80/443. Сначала используется HTTP (`NGINX_HTTPS=false`); для HTTPS нужны сертификаты в томе `letsencrypt` и переключение `NGINX_HTTPS=true`. Если перед Nginx есть ещё один proxy/WAF, отдельно настройте доверенные адреса и исключите прямой обход origin.

Убедитесь, что bind-mounted `media`, `staticfiles`, `imports` и `backups` доступны UID/GID 1000. Не исправляйте права через `chmod 777`. `rates` можно запустить отдельно; демокаталог с фиксированными ценами не требует загрузки курсов.

## Backup

Скрипты в `deploy/backup/` рассчитаны на Linux с Docker Compose и systemd. Перед установкой изучите `install.sh`: он устанавливает системные пакеты и копирует скрипты в root-owned каталог.

- полный snapshot — ежедневно; хранение 3 суток;
- PostgreSQL-only — каждые 2 часа; хранение 48 часов;
- maintenance `check → forget → prune` — ежедневно;
- проверка части данных и изолированное восстановление БД — еженедельно.

Время соответствует часовому поясу сервера; таймеры добавляют случайную задержку. Удаление snapshot через `forget` не освобождает все блоки сразу: физическая очистка выполняется `prune`. Это не жёсткий лимит размера бакета.

Шаблон секретов: `deploy/backup/backup.env.example`. Настоящие файлы хранятся вне приложения:

```text
/etc/finder/backup.env
/etc/finder/restic-password
```

Оба файла должны принадлежать root и иметь права `0600`. Restic-пароль сохраните также вне сервера: без него S3-копии не восстановить. Доступ сервера на запись и удаление не защищает репозиторий от компрометации root; для такой угрозы нужна отдельная архитектура хранения.

До включения таймеров выполните первый backup, проверку репозитория и тест восстановления. Используйте `--help` у `backup.sh`, `verify.sh` и `restore.sh`; восстановление делайте сначала в пустой отдельный каталог/одноразовую БД, не поверх production.

Offline-тест проверяет сценарии с подставными командами. Он не доказывает доступность S3, качество реального dump или успешность восстановления ваших данных.
